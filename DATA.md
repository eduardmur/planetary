# Data

Every number in Planetary comes from NASA's
[Planetary Fact Sheets](https://nssdc.gsfc.nasa.gov/planetary/factsheet/), maintained by Dr. David R.
Williams at the NASA Space Science Data Coordinated Archive (NSSDCA). This page says where each value
comes from, how it is parsed and where NASA's own pages disagree.

## Files

| File                           | What it is                                                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `data/raw/*.html`              | The NASA pages as downloaded: the main table, the ratio-to-Earth table, the three notes pages, the ten body pages and the four ring pages. |
| `data/raw/manifest.json`       | Each page's URL, size, SHA-256 and the retrieval time. The parser refuses a page whose hash does not match.                                |
| `src/data/factsheet.json`      | Everything parsed from those pages (schema below).                                                                                         |
| `data/factsheet-main.csv`      | NASA's main table, values as printed.                                                                                                      |
| `data/discrepancies.md`        | Where NASA's pages disagree, with each other or within one page, generated by `scripts/ledger.ts`.                                         |
| `src/data/discrepancies.json`  | The conflicts from the same ledger, keyed by body and row; each shows in the definition of the row it concerns.                            |
| `tests/fixtures/horizons.json` | JPL Horizons positions used to check the orbit model.                                                                                      |

The JSON and CSV are also served with the site, at `/planetary/data/`.

## Rules

1. **Values keep NASA's text.** Each value is stored as `{ text, value }`: `text` is the string as
   printed (`"1,432.041"`, `"~41,900"`, `"16,298."`, `"Unknown"`, `"18.28 - 28.58"`), `value` is the
   number it states, or `null` when it states none. Qualifiers (`~`, `<`, `>>`), ranges and footnote
   markers (`*`, `**`) are kept in their own fields.
2. **Nothing is rounded, converted or corrected.** Where NASA's pages disagree, each page's value is
   shown where that page prints it.
3. **A drawing is sized by the value printed on it.** The body's diameter, obliquity and rotation come
   from the main table, and so do the orbit's perihelion, aphelion and inclination. Values only a body
   page gives — polar radius, core radius, dipole tilt, ring radii — are labelled at their geometry.
   Computed values are shown in parentheses with their formula, for example Earth's dipole tilt
   `(9.35°) = 90° − 80.65°`, derived from NASA's geocentric dipole latitude.
4. **What NASA does not give is not drawn.** NASA gives no prime meridian, no direction for a dipole's
   offset, no longitudes for Neptune's ring arcs and no node or perigee longitude for the Moon, so
   none of these appear; the sheets say so where it matters.

## Orbits and positions

Orbit orientation and the position on the date come from each body page's "Mean Orbital Elements
(J2000)" and its sidereal orbit period, propagated with Kepler's equation (`src/astro/`). NASA gives no
rates of change, so the ellipses are fixed. Against JPL Horizons, checked every day from 1990 to 2060, the model stays
within 0.5° of heliocentric longitude for Mercury and 0.3° for every other body, 0.05° in latitude and
0.2% in distance. Mercury drifts most because its period is printed to three decimals. The tests hold
the measured worst cases per body.

The only number in the code that does not come from the fact sheets is the obliquity of the ecliptic at
J2000, 84381.448″, which defines the ecliptic frame relative to the equatorial one.

## Where NASA's pages disagree

`data/discrepancies.md` lists every value where NASA's pages disagree, between pages or within one:
the main table against each body page, and a page against the numbers it is worked out from on the
same page. In the current snapshot there are 18 conflicts and 103 differences that are only rounding.
Each conflict also shows in the popover of the row it concerns, saying whether two pages disagree or
one page disagrees with itself. Examples:

- The main table gives Pluto's eccentricity as 0.244, while its own perihelion (4436.8) and aphelion
  (7375.9) give 0.2488. The main table uses the J2000 mean orbit for Pluto's distances and a 2020 value
  for its eccentricity. Planetary draws Pluto's ellipse from the perihelion and aphelion and lists 0.244
  as NASA prints it.
- Mercury's and the Moon's main-table diameters (4879, 3475 km) are twice the mean radius, not the
  equatorial radius (2440.5, 1738.1 km) that NASA's notes define the diameter by.
- Pluto's page prints its surface temperature as `24 - 38 K (-247 - -233 C)`; 24–38 K is −249 to −235 °C.
- Uranus's ring sheet lists the Eta, Delta and Epsilon rings' radius/equatorial-radius ratios as 1.834,
  1.900 and 2.006, while their radii in km give 1.846, 1.890 and 2.001. Planetary draws the rings from
  the km column.

Two smaller quirks the parser handles explicitly: the ratio table links "Obliquity to Orbit" to an
anchor (`#orbo`) that its notes page does not have (the definition is there as "Axial Tilt", `#axit`),
and the ratio table repeats the moon count and the yes/no rows unchanged, so the sheets show no ratio
for those.

NASA's notes are candid about this: "the values listed on the factsheets are not 'official' values,
there is no single set of agreed upon values … care should be exercised when using these values."

If a value here does not match NASA's page, please open an issue with the page URL. If NASA's page
itself looks wrong, its curator's address is at the bottom of every fact sheet.

## Refreshing

```sh
npm run data:fetch    # download the pages again (updates data/raw/ and manifest.json)
npm run data:parse    # parse into src/data/factsheet.json and data/factsheet-main.csv
node scripts/ledger.ts
```

A scheduled GitHub Action does this every week and opens a pull request when anything changed. The
parser fails on any label, unit, heading or ring cell it does not recognise, so a change in NASA's page
layout stops the refresh instead of producing quietly wrong data.

## Schema

`src/data/types.ts` documents every field. In short:

```ts
interface FactSheet {
  source: string; // https://nssdc.gsfc.nasa.gov/planetary/factsheet/
  retrieved: string; // ISO time of the snapshot
  main: MainTable; // 20 rows × 10 bodies, with each row's notes anchor
  ratio: MainTable; // NASA's ratio-to-Earth table
  bodies: Record<BodyId, BodySheet>; // bulk, orbital, observational, elements, pole,
  //                                    magnetosphere, atmosphere, composition, rings,
  //                                    satellites (Mars, Pluto), footnotes
  definitions: Definitions; // NASA's notes pages, verbatim (terms keyed by row, plus unkeyed ones)
}
```
